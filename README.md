# Копить

Приложение для учета доходов и расходов.

Минималистичный учёт денег для фрилансера. Крупный чёрный текст, белый фон, адаптивный интерфейс для телефона и компьютера.

Инструкции размещения на сервере: [DEPLOY.md](DEPLOY.md). Docker Compose сохраняет SQLite в постоянном томе и обеспечивает HTTPS через Caddy.

## Версия с Supabase

Настоящая статическая версия с входом по почте, восстановлением пароля и хранением данных в Supabase: [SUPABASE.md](SUPABASE.md). Сборка `python3 build_cloud.py` создаёт `docs/app/` для GitHub Pages. Старый Python/SQLite вариант ниже запускается отдельно.

## Проверить интерфейс без регистрации

Откройте `kopit-demo.html` обычным браузером: он работает без сервера и Интернета. Все изменения остаются только в памяти открытой страницы и сбрасываются при её перезагрузке. В демо есть примерные суммы, категории и цели. Для пересборки файла после изменений выполните `python3 build_demo.py`.

При серверном запуске главная страница также открывает демо. Полная версия с аккаунтами доступна по пути `/?live=1`. Для GitHub Pages достаточно опубликовать содержимое `web/`: демо не требует серверной базы.

## Запуск

Нужен Python 3.10 или новее. Внешних зависимостей нет.

```sh
cd /workspace/Kopit
python3 server.py
```

Сервер по умолчанию слушает `127.0.0.1:8000`. Для доступа извне задайте `KOPIT_HOST=0.0.0.0` и настройте HTTPS перед сервером. При HTTPS задайте `KOPIT_SECURE_COOKIE=1`. `PORT` меняет порт, `KOPIT_DB` — путь к SQLite, `KOPIT_TIMEZONE` — часовой пояс сервера (по умолчанию `Europe/Moscow`; интерфейс первой версии использует московское время).

Аккаунт создаётся с электронной почтой и паролем от восьми символов. Вход с другого устройства в тот же аккаунт показывает общие данные; обновление каждые 15 секунд. При конфликте изменений сервер отклоняет устаревшую запись и предлагает повторить действие. Пароли хранятся как scrypt-хеши с индивидуальной солью, сессии — в HttpOnly-cookie.

## Начало работы

После первого входа пройдите опросник: бюджет на месяц → доступные деньги без отдельных целей → остаток на месяц → уже потрачено → резерв → накопления на второй месяц → цели → категории → проверка. Каждый экран задаёт один вопрос. Начальные остатки сохраняются одним действием и не попадают в историю доходов или расходов. Сумма, уже потраченная до регистрации, учитывается только в текущем месяце. До окончательного подтверждения ответы остаются черновиком открытой страницы. Заполненные аккаунты опросник не показывают.

Для проверки опросника в демо добавьте к адресу `?setup=1`: это новый пустой пример, без изменения данных аккаунта. При перезагрузке демо начинается заново.

## Как считаются деньги

- Бюджет по умолчанию 175 000 ₽, меняется в настройках. Категории необязательны для доходов, обязательны для расходов. Сумма заданных лимитов категорий не превышает бюджет; есть категории без лимита. Превышение лимита не запрещает записать реальный расход.
- Каждый доход сначала обеспечивает бюджет текущего месяца с учётом уже потраченного, затем резерв на следующий месяц. Остаток доступен для ручного распределения по целям.
- Пример: текущий месяц уже обеспечен, резерв пуст, поступило 200 000 ₽. В резерв уйдёт 175 000 ₽, на цели останется 25 000 ₽. Если текущий месяц ещё не обеспечен, он финансируется первым.
- Дополнительный месяц запаса — отдельная цель, изначально первая по приоритету. Порядок целей меняется стрелками. Её накопления не расходуются автоматически; можно записать расход внутри цели.
- Неизрасходованные деньги переносятся на следующий месяц. Из резерва добавляется только недостающее до месячного бюджета. Оставшийся резерв сохраняется. Переход месяца выполняется при обращении к серверу, без отдельного фонового процесса.
- Недельный ориентир: остаток месяца / оставшиеся дни месяца × дни до ближайшего воскресенья или конца месяца. Это ориентир, а не отдельный кошелёк.
- Расходы из цели уменьшают только её накопления. Начальные накопления цели указываются отдельно и не списываются из текущего бюджета. Деньги считаются целыми копейками.
- Распределение показано цветной кольцевой диаграммой. Выберите цель, перемещайте белые ручки на границах сегментов пальцем или мышью: суммы соседних целей изменяются с шагом 2 000 ₽. Серый сегмент — нераспределённые деньги. Поля суммы позволяют точный ввод, стрелки клавиатуры управляют выбранной ручкой. При открытии каждая цель получает одинаковую базовую сумму, кратную 2 000 ₽. Весь остаток добавляется первой цели по приоритету, поэтому вся доступная сумма распределяется без потерь. Это предложение применяется только после подтверждения.

## Проверка

```sh
python3 -m unittest discover -s tests -v
node --check web/app.js
```

Дополнительная проверка интерфейса (если установлен Playwright и `/usr/bin/chromium`):

```sh
python3 tests/browser_smoke.py
```

Тесты проверяют финансовые правила, перенос месяца, сохранение через HTTP, вход, синхронизацию двух клиентов, изоляцию аккаунтов, конфликты и атомарность отклонённых операций. Тестовый сервер использует временную базу, не затрагивая пользовательские данные.

## Хранение и ограничения первой версии

Данные сохраняются в `data/kopit.sqlite3`, этот каталог исключён из Git. Для резервного копирования используйте SQLite backup API или останавливайте сервер перед копированием базы. В настройках есть выгрузка финансовых записей в JSON.

Ежедневные и ежемесячные напоминания работают при открытом приложении; системные уведомления требуют разрешения браузера. Push при закрытом браузере, отдельное мобильное приложение, валюты кроме рубля, подтверждение почты и восстановление пароля пока не реализованы. Необходим отдельный этап размещения на HTTPS-сервере для доступа с разных устройств через Интернет. Перед публичной эксплуатацией также нужны почтовый сервис для восстановления доступа, резервное копирование и эксплуатационная настройка сервера. Приложение не подключается к банкам.

## Варианты дизайна

`design-ideas.html` — автономная галерея восьми визуальных направлений, по две страницы в каждом. Это эскизы для выбора стиля. Рабочее демо с интерактивной диаграммой находится в `kopit-demo.html`.

## Пошаговое заполнение дня

На главной кнопка «Заполнить день»: сегодняшний день выбран автоматически. Категория → сумма → ещё расход или итог → завершение. Теги доступны отдельно по желанию. До подтверждения записи остаются в черновике. Расходы сохраняются одной атомарной операцией; неудачный запрос не сохраняет часть записей. Можно заполнить другой прошедший день текущего месяца или отметить день без расходов. Ежедневное уведомление открывает тот же сценарий; доставка по-прежнему требует открытого приложения и разрешения браузера.

## Навигация и инструкция

Меню закреплено снизу: обзор, категории, цели, история, настройки, инструкция. По умолчанию значки сопровождаются подписями; в настройках можно включить только пиктограммы. В формах изменения категории и цели выбирается своя пиктограмма. Инструкция объясняет идею стабильного бюджета для фрилансера в шести шагах и содержит снимки реального демоинтерфейса. В автономный HTML встроены все снимки, поэтому интернет не требуется.

## Внешний вид

В жёлтой карточке осталась одна кнопка «На что потратил». Поступления записываются отдельной кнопкой «Добавить доход» между карточкой месячного бюджета и блоком «Как прошёл день?». Выбор пиктограммы категории или цели — сетка из 40 рисунков. В пошаговом заполнении дня новая категория создаётся в два отдельных шага: название и рисунок. Инструкция описывает действия и расчёты без образных формулировок.

## Разделы истории

История фильтруется по месяцу и вкладкам «Все», «Доходы», «Накопления» (пополнения целей), «Расходы» (месячный бюджет), «Цели» (расходы из накоплений). Суммы вкладок показывают операции выбранного месяца, а не общий баланс накоплений. Во вкладке «Все» показано количество записей.

В GitHub откройте Settings → Pages → Deploy from a branch, выберите `main` и `/docs`, затем Save. После успешной публикации ожидаемый адрес: `https://phototur.github.io/Kopit/`. Это демо: изменения сбрасываются при перезагрузке страницы.
