# Размещение на сервере

Подготовлен вариант для Linux-сервера с Docker Compose: приложение, постоянный том SQLite и Caddy с автоматическим HTTPS. Это конфигурация для размещения, а не уже работающий публичный сайт.

## Бесплатный вариант

Можно использовать виртуальную машину Oracle Cloud Always Free, если бесплатные ресурсы доступны в выбранном регионе и регистрация проходит. Провайдер может потребовать банковскую карту для проверки. Доступность, условия бесплатного тарифа и возможные начисления нужно проверить в личном кабинете до создания ресурсов. Не выбирайте платные ресурсы. Бесплатная машина не заменяет внешние резервные копии: провайдер может отозвать ресурсы.

Бесплатный Render без постоянного диска не подходит для текущей SQLite-базы: локальные записи могут исчезнуть при пересоздании приложения. Для такого размещения сначала нужна отдельная постоянная база и адаптация приложения. Не размещайте эту версию с пользовательскими данными на временном файловом хранилище.

Собственный домен необязателен: можно использовать бесплатный DNS-поддомен, направленный на IP машины. Например, провайдер динамического DNS. Убедитесь, что поддомен действительно закреплён за вами.

## Необходимое

- Linux VM, Docker Engine и Compose plugin.
- Публичный IP и DNS-имя с A-записью на этот IP.
- Входящие TCP 80 и 443 разрешены в сетевых правилах провайдера и firewall машины. Порт приложения 8000 не нужно открывать.
- Доступ SSH к машине. Не передавайте приватные ключи и пароли в чат.

## Запуск

Перенесите исходники на сервер без `data/`, `.env` и других личных данных. Если нужно перенести существующую базу, сначала сделайте согласованную SQLite-копию; не копируйте работающий файл базы отдельно от WAL.

В каталоге проекта выполните, заменив `your-domain.example` настоящим DNS-именем:

```sh
export KOPIT_DOMAIN=your-domain.example
docker compose config --quiet
docker compose up -d --build
docker compose ps
```

Caddy получает сертификат автоматически. Откройте `https://` с вашим доменом и создайте аккаунт. Не вводите пароль до появления корректного HTTPS-соединения. Для проверки:

```sh
curl --fail --silent --show-error "https://$KOPIT_DOMAIN/" >/dev/null
docker compose logs --tail=50 app proxy
```

Проверьте вход, запись дохода и расхода, вход с второго устройства. Затем выполните `docker compose restart app` и убедитесь, что записи сохранились. В команде проверки API `/api/state` без сессии ожидается HTTP 401.

Для обновления исходников: `docker compose up -d --build`. Не используйте `docker compose down -v`: флаг `-v` удаляет тома вместе с базой и сертификатами. Обычный `docker compose down` сохраняет тома.

## Резервная копия

Создайте согласованную копию через SQLite backup API:

```sh
docker compose exec -T app python -c 'import sqlite3; a=sqlite3.connect("/data/kopit.sqlite3"); b=sqlite3.connect("/data/backup.sqlite3"); a.backup(b); b.close(); a.close()'
mkdir -p backups
docker compose cp app:/data/backup.sqlite3 ./backups/kopit.sqlite3
chmod 600 ./backups/kopit.sqlite3
```

Храните резервную копию вне сервера в защищённом месте. Она содержит персональные финансовые данные и хеши паролей. Не добавляйте её в Git.

У первой версии нет подтверждения почты и восстановления пароля. Для личного использования выбирайте уникальный пароль и сохраняйте его в менеджере паролей. Перед открытой регистрацией для других пользователей нужны дополнительная защита регистрации, почтовый сервис и эксплуатационная настройка.
