# Настройка настоящей версии

HTML, CSS и JavaScript размещаются на GitHub Pages. Supabase хранит аккаунты и записи; браузер обращается к нему по HTTPS. Python-сервер для этой версии не нужен. Демо остаётся по основному адресу, версия с аккаунтами — в `/Kopit/app/`.

1. В Supabase откройте **SQL Editor → New query**. Скопируйте целиком `supabase/migrations/202610100001_accounts.sql` и нажмите **Run**. Скрипт создаёт таблицу, правила доступа и функции чтения/сохранения. Повторный запуск не удаляет записи.
2. Откройте **Authentication → URL Configuration**. Укажите **Site URL** `https://phototur.github.io/Kopit/app/` и добавьте этот же адрес в **Redirect URLs**. Если выбран другой хостинг, используйте его фактический HTTPS-адрес.
3. В **Authentication → Sign In / Providers → Email** включите вход по email и подтверждение почты. Настройте SMTP для писем реальным пользователям: встроенная отправка Supabase имеет ограничения и может разрешать письма только участникам команды. Для первого теста можно использовать почту владельца проекта.
4. Публичные URL и publishable key уже указаны в `web/supabase-config.js`. Не добавляйте secret key или service_role в браузерные файлы.
5. Сборка: `python3 build_cloud.py`. Результат — `docs/app/`. В GitHub **Settings → Pages** выберите ветку `main`, папку `/docs`, затем **Save**. Бесплатный GitHub Pages требует публичного репозитория; видимость меняется отдельно владельцем в General → Danger Zone.
6. После успешного развёртывания откройте `https://phototur.github.io/Kopit/app/`, создайте аккаунт, подтвердите почту и войдите. Создайте категорию, добавьте доход и расход, затем войдите тем же аккаунтом в другом браузере и проверьте записи.

На iPhone: откройте адрес в Safari → Поделиться → На экран «Домой». Интерфейс учитывает вырез и нижнюю безопасную область экрана. Записи сохраняются только при наличии соединения; офлайн-режима и уведомлений при закрытом приложении пока нет.

## Доступ и ограничения первой версии

Каждому аккаунту соответствует собственная запись JSON в базе. RLS разрешает чтение только владельцу. Прямое изменение таблицы запрещено; сохранение выполняется функцией, которая определяет владельца по авторизации и проверяет ревизию. Устаревшее сохранение с другого устройства отклоняется, после обновления нужно повторить действие. Все расходы из дневного мастера сохраняются одним запросом. Расчёты выполняются в браузере; база проверяет структуру и основные суммы. Это личный учёт, не банковская система.

В браузере хранится сессия Supabase, чтобы сохранять вход после перезагрузки. Финансовые записи загружаются из базы. Кнопка «Выйти» удаляет сессию этого браузера. Первый вход открывает пошаговую настройку. Укажите месячный бюджет, доступную сумму без накоплений на цели, остаток текущего месяца, уже потраченное и резерв. Затем добавьте накопления на второй месяц, цели и категории. На итоговом экране подтвердите все ответы одним сохранением. До подтверждения это черновик в открытой странице; перезагрузка начинает опросник заново. Начальные суммы не создают фиктивные операции в истории. Заполненные аккаунты повторно не настраиваются; данные демо автоматически не переносятся. Для нового опросника повторять SQL-миграцию уже настроенной базы не требуется.

При ошибке «База ещё не настроена» выполните SQL из пункта 1. Подключение к реальному проекту можно считать проверенным только после успешных регистрации, входа и записи в него.
